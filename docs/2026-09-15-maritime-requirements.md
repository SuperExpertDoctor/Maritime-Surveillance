# 海上违法作业船舶搜索与识别：修改需求汇总

> 术语已按 2026-09-16 统一：分类使用 I 类船舶/II 类船舶，运行时值使用 `type_i`/`type_ii`。

日期：2026-09-15

本文依据本轮需求讨论整理，以用户最后确认的术语和规则为准。本文是需求记录，不是已完成实现的说明，也不代表性能指标已经达标。示例数字不构成默认配置；标为“待确认”的事项不得作为既定实现行为。

## 1. 项目场景与任务范围

项目面向海上违法作业监管，使用多 UAV 执行区域搜索、船舶识别与持续观察。

场景包含两类船舶：

- **I 类船舶**：正常航行或作业，开启 AIS。
- **II 类船舶**：本项目场景中的违规作业对象，承担此前讨论中“目标船舶”的搜索、识别、持续观察及接力任务；AIS 可开启或关闭。

后续统一使用“I 类船舶”和“II 类船舶”，不沿用此前“船舶”的称谓。当前需求不包括遇险判断和救援流程。

AIS 在本项目中是触发全局信息价值调整的信号，不包括身份伪造、坐标伪造或欺骗功能。AIS 开关本身不直接给出船舶类别或违规结论。

场景真值与算法识别结果须区分：场景可以预设船舶类别，但算法不能直接读取隐藏类别标签完成识别。“违规作业”的具体可观测行为尚待定义，不能仅凭II 类船舶类别或 AIS 关闭推断违规。

## 2. 三块算法架构

| 模块 | 职责 | 主要交互 |
| --- | --- | --- |
| 信息管理 | 接收观测与事件，维护信息状态、更新全局信息价值、执行时间衰减 | 提供统一读取接口，接收观测及执行反馈 |
| LLM 任务规划与调度 | 读取信息价值和资源状态，组装 Prompt，规划任务区域与 UAV 调度 | 接收信息快照，向执行端提交任务 |
| 单机执行 | 接收指定 UAV ID 和任务区域，执行覆盖搜索与持续观察 | 报告观测、任务进展、返航及接力相关事件 |

```text
传感器观测、AIS、识别结果、执行事件
                  ↓
        全局信息状态与价值更新
                  ↓
       信息读取与 LLM Prompt 组装
                  ↓
        LLM 任务规划与 UAV 调度
                  ↓
             单机任务执行
                  ↓
           新观测与执行反馈
```

各种后端机制通过共享信息状态影响上层规划。观测事实、规划结果、任务执行事实需要区分，不能仅凭价值更新或任务提交就认定任务完成。

本次要求明确模块职责，不等于要求将三块拆成独立部署的服务。

## 3. 信息新鲜度与信息价值

沿用项目已有信息管理机制，不重新定义一套相互冲突的“信息量”。

| 量 | 含义 |
| --- | --- |
| `I` | 观测新鲜度；扫描后升高，随后随时间衰减 |
| `V` | 规划关注价值；表示区域有多值得安排任务关注 |

用户所说“信息量越高，LLM 越应该聚焦这里”，对应 `V`。高价值是规划依据，不代表无条件立即指派。

此前静态审查确认 `src/schedule/info_field.py` 已有如下计算关系：

```text
V = clip(α × (1 − I) + β × S + γ × A, 0, 1)
```

其中已有标记相关分量参与价值计算；本文不重新规定权重和衰减参数。

**示例：**区域 A 刚获得有效扫描，区域 B 长期没有新观测。在其他条件相近时，B 的信息缺口增加，可能更值得进入后续规划考虑。

### 3.1 信息更新来源

- 区域扫描与持续观察产生的新信息。
- AIS 接收及其更新资格变化。
- 船舶类别识别结果。
- 被动信号传感器的方位或位置证据。
- 低油量返航、观察中断和接力需求等执行事件。
- 时间流逝产生的新鲜度及相关价值变化。

这些来源通过明确接口进入信息管理，同时保留证据语义。例如方向证据不能被当成精确位置证据，时间衰减不能被当成船舶消失。

## 4. UAV 数量与自主执行

- UAV 数量作为显式超参数。
- 正式能力目标支持至少 10 架 UAV。
- 初始化、资源管理、调度、执行和界面使用实际配置数量，不能局部读取配置、其他位置仍固定为 10。
- 单机具备区域覆盖搜索、持续观察、传感器切换及平台姿态调整能力，并遵守物理约束。

**示例：**配置 12 架 UAV 后，应创建、展示并管理 12 架。是否允许更小规模用于调试未被禁止，但不能代替 ≥10 架的能力验收。

## 5. 三类传感器及观测边界

| 传感器 | 已确认要求 |
| --- | --- |
| 雷达／SAR | 区域覆盖搜索 |
| 光电 | 船舶持续观察与跟踪 |
| 被动信号传感器 | 全程开启，接收外部辐射信号 |

被动信号传感器不因主任务或 SAR／光电切换而被顺带关闭。雷达和光电能否同时开启、具体切换耗时尚待确认。

### 5.1 方位与位置证据

- 单架 UAV 有效接收时，只能获得信号方位，不能直接获得精确位置。
- 多架 UAV 的有效观测是形成位置估计的前提。
- 不能读取仿真真值坐标冒充传感器测量。
- 只有方位时，信息更新表达方向线索；获得有效位置估计时，才可表达相应位置证据。

**示例：**只有 UAV A 接收到信号时，系统表达“某个方向存在信号线索”，不能直接显示一个已精确发现的船位。

多机接收范围重叠不自动保证可靠定位，具体观测有效性条件尚待定义。

### 5.2 II 类船舶信号行为

II 类船舶可以随机发射雷达信号，供被动信号传感器接收。随机发射的概率、间隔和持续时间尚未确定。

## 6. AIS 规则

### 6.1 AIS 不包含欺骗功能

AIS 仅作为本项目的信息更新触发来源，不引入伪造身份、伪造坐标或欺骗报文。

| 状态 | 含义 |
| --- | --- |
| AIS 开启／关闭 | 船舶是否发送 AIS |
| AIS 更新 `status` 有效／无效 | 接收该信号后，是否允许触发全局信息价值调整 |

I 类船舶开启 AIS；II 类船舶可开启或关闭。发送开关与更新资格不可混淆。

### 6.2 I 类船舶确认后的过滤

船舶被确认为I 类船舶后，其 AIS 更新 `status` 标记为无效。后续仍可接收该船 AIS，但这些信号不再改变全局信息价值分布。

**示例：**

1. 船舶 A 发送 AIS，类别尚未确认，按有效信号规则处理。
2. 后续识别确认 A 为I 类船舶。
3. 将 A 对应 AIS 的更新资格设为无效。
4. A 继续发送 AIS，但后续报文不再触发 `V` 更新。

这一规则不等于删除船舶、关闭其 AIS，也不冻结该区域的时间衰减或其他观测来源。

**待确认：**确认I 类船舶以前已经产生的 AIS 价值影响是否追溯撤销。目前只确认“后续不再更新”。

## 7. 船舶数量与组成配置

显式设置以下超参数：

- 船舶总数量。
- I 类船舶占比。
- II 类船舶占比。

只有这两类船舶时，占比之和为 100%，整数船数之和必须等于总数。

| 示例配置 | 数值 |
| --- | --- |
| 总船数 | 20 |
| I 类船舶占比 | 70% |
| II 类船舶占比 | 30% |
| 实际生成 | 14 艘I 类船舶、6 艘II 类船舶 |

**待确认：**比例取整规则；两个比例是否联动输入；手动增删后是否改写初始化总数与比例，还是仅改变当前场景实际数量。

## 8. 右侧船舶组件库与地图编辑

这是已明确确认的界面需求：

- **界面右侧设置组件库，包含“I 类船舶”和“II 类船舶”。**
- **支持将对应组件拖拽到地图位置，创建该类船舶。**
- 支持点击组件后，再点击地图放置。
- **支持选中地图上的已有船舶并移除。**
- 放置位置必须在整体任务边界内。

**示例：**从右侧拖入“II 类船舶”组件至地图合法位置，新增一艘II 类船舶；选中该船后可删除。I 类船舶采用相同交互。

**待确认：**

- 仅初始化阶段允许编辑，还是仿真运行中也可编辑。
- 新船初始航向、速度和 AIS 状态如何确定。
- 非法放置的具体交互反馈。
- 删除后的已有任务、信息贡献与历史记录如何处理。

## 9. 船舶运动边界

所有船舶在初始生成、手动放置和后续运动过程中，均不得越出**整体任务边界**。该边界不是某架 UAV 的局部任务区域。

**示例：**船舶虽然初始位置合法，但继续前进将越界时，后续运动结果仍须留在整体任务区域内。

**待确认：**抵达边界后的具体行为，例如转向、停止或重新选航路。当前只确认“不允许越界”，不默认选择任何一种处理。

## 10. 搜索、识别、持续观察与接力

II 类船舶承担重点搜索、识别和持续观察任务。UAV 油量不足时返航，相关执行事件进入信息管理，后续由其他 UAV 接续尚未完成的任务。

**示例：**UAV A 需要退出观察任务时，系统保留任务未完成及需要接续的事实，不能将 A 退出视为整个任务完成。

用户此前提出提高“最后返航相关区域”的信息价值以引导后续关注，但其空间含义尚未确定：最后有效观测位置、离开任务时的位置，还是返航路径附近。不能直接解释为基地附近。

用户认为现有系统已经有接力机制；后续应核查现有链路，不直接宣称已达到成功率要求。

**待确认：**具体违规作业行为、最初提到的“逃逸行为”的仿真定义，以及哪些观测构成识别依据。不能未经定义将正常转向、绕行或 AIS 关闭直接作为违规结论。

## 11. LLM 与候选区域的现有实现差异

用户期望 LLM 根据全局信息价值进行区域规划与 UAV 调度。此前静态代码审查确认，当前新增区域链路为：

1. 后端生成并筛选有限候选矩形。
2. Prompt 向 LLM 提供候选及摘要。
3. LLM 选择候选。
4. 校验器要求新增矩形匹配允许的候选矩形。

相关位置包括 `src/schedule/candidate_extractor.py`、`prompt_builder.py`、`llm_client.py` 和 `output_validator.py`。文档描述的 UAV 配对另有确定性算法参与，不能认为全部具体 UAV ID 均由 LLM 直接选择。

**用户关注点：**筛选与截断可能使部分合法区域不进入本轮决策范围。

**示例：**A、B、C 均为合法区域，但只提交 A、B，LLM 本轮就无法选择 C。本轮没有进入候选不等于永远不会进入，但现有静态审查也没有证明最终覆盖保证。

**待决策：**候选提取应保留何种职责、全局信息如何呈现、LLM 是否允许生成候选以外的边界。用户尚未决定删除候选机制，不能自行将其列为已批准修改。

## 12. 指标与暂缓事项

| 指标或约束 | 当前要求 |
| --- | --- |
| UAV 规模 | ≥10 架，数量显式配置 |
| 传感器类型 | 固定三类 |
| 船舶发现与跟踪任务完成率 | ≥85%，统计口径待明确 |
| I 类船舶与违规作业II 类船舶区分率 | ≥85%，统计口径待明确 |
| 接力及持续观察成功率 | ≥85%，统计口径待明确 |
| 在线规划与控制优化响应 | ≤2 秒，计时起止点待明确 |
| LLM verify、“合理程度 ≥85%”评价 | 按用户要求暂不关注 |
| 物理、传感器和边界约束 | 继续遵守，不因暂缓评分而取消 |

评价需明确分母、成功条件、失败处理，以及时间采用实际墙钟还是仿真时间、是否包含排队和重试。本文不补充未经确认的评价阈值，也不声称已有结果达标。
