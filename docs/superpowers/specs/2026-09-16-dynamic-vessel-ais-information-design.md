# I/II 类船舶动态管理、AIS 与信息场闭环设计

日期：2026-09-16  
状态：待用户审阅

## 1. 目标

系统只使用两类船舶：I 类船舶和 II 类船舶。操作员可在实时仿真期间新增、删除船舶，并可动态切换 II 类船舶的 AIS 发射状态。I 类船舶始终开启 AIS，按确定性规则航行；II 类船舶在受到 UAV 递进侦察和跟踪后，由红方 LLM 动态调整逃逸机动参数，但最终轨迹仍由确定性导航、动力学、边界和避障模块生成。

本次同时收敛全局信息状态，使 AIS、SAR、EO、被动信号、识别、接力和时间衰减均通过同一个版本化更新边界影响任务规划。

## 2. 术语与迁移范围

新的权威分类契约为：

```text
vessel_class = type_i | type_ii
```

| 类别 | 行为 |
| --- | --- |
| I 类船舶 (`type_i`) | AIS 始终开启；只按规则航行；不接受红方 LLM 机动参数 |
| II 类船舶 (`type_ii`) | AIS 可动态开启或关闭；进入递进侦察阶段后可接受红方 LLM 逃逸机动参数 |

术语迁移覆盖源代码、类型定义、API、配置、事件、日志、Prompt、界面文案、测试、脚本、README 和 `docs/` 下的资料。新的运行时契约和资料不得继续使用“民船”“民用船舶”“科考船”“舰船”或对应的 `civilian`、`research`、`military`、`target` 分类值。

旧回放、旧日志和旧配置只在输入兼容层映射：

```text
civilian                 -> type_i
research/military/target -> type_ii
ais_mode=civilian        -> ais_enabled=true
ais_mode=silent          -> ais_enabled=false
```

兼容值不得重新进入新的帧、API、事件或持久化输出。与分类无关的自然语言（例如通用的“目标位置”）不属于迁移对象。

## 3. 船舶运行时状态

`Ship` 使用单一权威 AIS 发射状态：

```text
ais_enabled: bool
```

不再以 `ais_mode="civilian"/"silent"` 表示开关。所有 AIS 相关功能读取该字段，包括信号生成、接触摄入、红方快照、逃逸检测输入、信息证据、评估和前端帧。

AIS 发射状态与信息更新资格保持独立：

- `ais_enabled` 决定船舶是否发射 AIS。
- `ais_value_update_enabled` 决定收到该 MMSI 的报文后是否允许更新全局信息价值。

I 类船舶的 `ais_enabled` 始终为 `true`，服务端必须拒绝任何关闭命令。II 类船舶按配置概率初始化，之后允许操作员在实时仿真中切换。

关闭 AIS 后立即停止产生新报文。关闭前的航迹、接触、证据和信息价值贡献保留，并按既有 TTL 自然衰减。重新开启后在下一仿真步立即广播一次，随后恢复配置的周期广播。AIS 关闭本身不构成类别、违规或逃逸结论。

## 4. 运行期命令模型

扩展现有线程安全船舶命令队列，支持：

```text
operation = create | delete | set_ais
```

所有命令包含 `command_id` 和 `episode_id`。删除和 AIS 修改还包含 `vessel_id` 与 `expected_revision`；AIS 修改包含 `ais_enabled`。命令保持幂等，并使用 revision compare-and-swap 防止旧界面状态覆盖新状态。

创建、删除和 AIS 切换在实时仿真期间均可执行，回放模式保持只读。命令只在仿真线程应用：

1. 校验 episode、revision、船舶类别和操作权限。
2. 校验创建位置、水域、间距、连续安全性和可行航路。
3. 原子修改船舶、发射器、红方计划引用、任务引用和版本。
4. 发布审计事件并在下一帧返回权威状态。

禁止 API 请求线程直接修改船舶实体。

### 4.1 运行期创建

- I 类船舶创建后固定开启 AIS，并进入规则导航。
- II 类船舶创建后生成独立航路、雷达发射器和 AIS 初始状态。
- 新船立即进入动态船舶注册表和后续评估，但仅在达到红方 LLM 激活条件后进入其活跃集合。
- 当前实际船舶数量随下一帧更新，不回写场景初始配置。

### 4.2 运行期删除

删除作为一个仿真线程事务执行：

- 立即停止运动、AIS 和雷达发射。
- 撤销该船的红方 LLM 机动参数并从活跃集合移除。
- 释放关联的 probe、track、接力任务和 UAV 占用，触发蓝方重规划。
- 移除物理实体和运行时索引，不允许残留悬挂引用。
- 保留历史 AIS、观测证据和审计日志，使其按 TTL 自然失效。

## 5. 递进侦察与动态红方 LLM

环境依据真实执行事实为每艘 II 类船舶维护侦察阶段：

```text
undetected -> detected -> probing -> tracking
```

| 阶段 | 判据 |
| --- | --- |
| `undetected` | 尚无 UAV 有效观测 |
| `detected` | SAR 或 UAV 被动传感器形成有效接触 |
| `probing` | UAV 正在执行递进识别任务 |
| `tracking` | UAV 已建立有效 EO 锁定并持续跟踪 |

全局卫星 AIS 可以形成接触和信息证据，但不单独推进 UAV 侦察阶段。阶段可随任务、传感器锁定和接触生命周期升级或降级。

`undetected` 的 II 类船舶与全部 I 类船舶按规则航行。处于 `detected`、`probing` 或 `tracking` 的 II 类船舶进入红方 LLM 活跃集合。每次红方快照包含：

- 当前活跃 II 类船舶 ID 和侦察阶段；
- 位置、航向、航速及当前机动参数；
- 附近 UAV 数量、距离和相对运动；
- 参数物理上下限和计划有效期。

红方 LLM 只返回 `heading_offset_deg`、`speed_kn`、`zigzag_heading_deg`、`zigzag_period_min` 和 `phase_deg`。响应必须精确覆盖当前活跃集合，不得包含轨迹、航路点、已删除船舶或 I 类船舶。

以下变化立即废止不匹配的旧计划并触发新决策：

- II 类船舶新增或删除；
- 侦察阶段升级或降级；
- 活跃集合变化；
- 当前计划到期。

现有 3 分钟红方周期作为兜底。单次在线决策继续受 2 秒墙钟预算约束。LLM 超时或返回非法结果时不得安装部分计划：只有在 II 类船舶集合和阶段仍完全匹配时才可继续使用未过期旧计划，否则进入现有 `paused_model` 状态并暴露失败原因。

## 6. 全局信息状态闭环

保留现有价值公式：

```text
V = clip(alpha * (1 - I) + beta * S + gamma * A, 0, 1)
```

所有变化统一进入 `InformationUpdatePolicy`：

```text
AIS / SAR / EO / 被动信号 / 识别 / 接力 / 时间衰减
  -> InformationUpdatePolicy
  -> InfoFieldDelta
  -> information_version + dirty bbox
  -> TriggerManager
  -> LLM 重规划或轻量重新匹配
```

具体规则：

- `scan_cell()` 和 `scan_bbox()` 返回 `InfoFieldDelta`，SAR/EO 调用方必须提交 delta 给触发器。
- 时间推进使用 `advance_time()` 检测新鲜度衰减、证据 TTL 到期和候选阈值穿越。
- 连续微小衰减不逐帧触发 LLM；相对上次已发布状态的累计最大变化达到 `0.05`、跨越候选阈值或证据到期时，增加版本并产生 delta。
- AIS 状态变化产生审计和重规划事件，但只有矩阵实际变化才增加 `information_version`。
- 新 AIS 报文仅在 `ais_enabled` 和该 MMSI 的 `ais_value_update_enabled` 均为真时形成新的 AIS 信息证据。
- 收敛旧 `InfoField` 与新策略的双写，使前端矩阵、候选生成、LLM 快照和版本校验读取同一权威状态。
- LLM 结果提交时校验 `information_version`，过期结果不得覆盖新状态。

新 II 类线索、AIS 开启或关闭、重要证据、证据到期和候选阈值穿越采用重量重规划。普通扫描刷新先累计 delta，达到门槛后重量重规划。搜索完成和资源恢复等现有事件继续使用轻量重新匹配。30 分钟周期只作为兜底。

## 7. 前端交互

右侧船舶组件库包含“I 类船舶”和“II 类船舶”两个放置工具。组件库及船舶列表在仿真运行期间保持可用，列表显示当前实际数量和每艘船的类别、revision 与 AIS 状态。

选中船舶后显示 AIS 分段控制：

```text
AIS 状态    [ 开启 | 关闭 ]
```

- I 类船舶固定高亮“开启”，控件禁用并显示固定状态。
- II 类船舶可切换；当前状态高亮，提交期间禁止重复操作。
- 重复选择当前状态不发送命令。
- 前端不乐观伪造成功状态，以后端帧中的 `ais_enabled` 和 revision 为准。
- 回放显示当时状态，但全部编辑控件只读。
- revision 冲突、非法位置、未知船舶、I 类关闭请求和服务不可用均在控制区显示明确错误。

数据流为：

```text
右侧操作
  -> POST/DELETE/PATCH 船舶 API
  -> VesselCommandQueue
  -> 仿真线程原子应用
  -> 审计与规划触发
  -> mission-frame/v2 权威状态
  -> 右侧列表与 AIS 控件刷新
```

## 8. API 与帧契约

保留创建、删除和命令查询接口，并新增：

```text
PATCH /api/vessels/{vessel_id}/ais
```

请求包含 `episode_id`、`command_id`、`expected_revision` 和 `ais_enabled`。服务端不得依赖前端禁用状态执行类别约束。

实时帧始终发布可操作船舶清单，不再只在初始化窗口发布：

```text
scenario_entity_id
revision
position
vessel_class = type_i | type_ii
ais_enabled
ais_controllable
surveillance_stage
```

回放适配器负责把旧字段转换为该形状；新日志直接保存新契约。

## 9. 失败处理

- 非法位置、未知船舶、旧 revision、I 类 AIS 关闭和回放写入返回稳定的可机读错误码。
- 同一 `command_id` 和相同载荷保持幂等；相同 ID 的不同载荷返回冲突。
- 运行时删除必须全成或全败，不得留下发射器、任务、接力、红方计划或索引残留。
- 红方 LLM 响应缺失、重复、越界参数、集合不匹配或超时均不得部分安装。
- 信息更新批次验证失败时，不增加版本且不产生部分字段更新。

## 10. 验收与测试

### 10.1 领域与迁移

- 新运行时契约、界面和资料只使用 I 类/II 类与 `type_i/type_ii`。
- 旧 `civilian/research/military/target` 数据仅在兼容输入测试中出现。
- 旧回放和旧配置可读取，新的输出不回写旧值。

### 10.2 AIS

- 任意创建和命令序列下，I 类船舶 AIS 始终开启。
- II 类切换后，信号生成、帧、红方快照、评估和信息更新读取相同状态。
- 关闭后不再生成新报文，旧证据自然衰减；开启后下一仿真步恢复广播。
- AIS 发射状态和 AIS 价值更新资格互不混淆。

### 10.3 动态船舶与红方 LLM

- 运行期间可新增、删除任意合法数量的 I 类和 II 类船舶。
- 删除活跃 II 类船舶后，无物理实体、任务、发射器或红方计划残留。
- 侦察阶段变化会更新 LLM 活跃集合并废止不匹配计划。
- 红方 LLM 只输出机动参数，轨迹始终由确定性导航和动力学生成。
- 多 seed 长时仿真验证船舶不越界且无悬挂任务。

### 10.4 信息闭环

- SAR、EO、AIS、被动方位、被动位置、识别、接力和时间衰减均能产生正确版本与 delta。
- 时间衰减达到门槛、跨越候选阈值或证据到期会触发重量重规划。
- 相同事实重放不增加版本；过期 LLM 结果被拒绝。
- 前端信息矩阵、候选池和 LLM 快照读取同一权威信息状态。

### 10.5 前端

Playwright 覆盖运行期放置、删除、动态计数、II 类 AIS 分段按钮、I 类固定状态、命令失败、revision 冲突和回放只读。

## 11. 非目标

- LLM 不直接输出或控制船舶轨迹。
- AIS 开关不提供身份伪造、坐标伪造或欺骗功能。
- 不因 AIS 关闭直接判定类别、违规或逃逸。
- 不拆分独立微服务，不引入新的消息中间件。
