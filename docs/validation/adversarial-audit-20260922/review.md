# 海上对抗仿真审查与修复（2026-09-22）

本次先将本地 main 从 `740fde4` 快进至远端 `4642a28d5aef3072253ecd2ba50d891c3e15cac3`（13 个提交），再恢复并复核修改。原始工作已留存于 `audit-20260922-before-main-sync` stash。没有将本次修改推送远端。

阵营按用户定义：**我方红方为 UAV 探测、核查与跟踪；对方蓝方为干扰与逃逸船舶**。内部兼容接口仍使用历史名称 `red_commander`、`RedPlan`、`red-plan/v1`，代表船舶对手，不代表用户定义的红方。对手提示词及新增事件已明确此映射。

## 1. 虚线框左侧为何没有覆盖

这是后端任务域与前端底图表达不一致，不是简单的 UAV 忘记搜索：

- 后端默认 `mainland_width_cells: 5`，第 0–4 列是陆地。岛屿、地图边界及基地也排除在固定 SAR 覆盖分母之外。
- 前端把整个 30×30 网格挪到装饰海图右侧，却标作 `TASK AREA / 300×300 KM`，没有画出排除区。于是算法认定的陆地看起来像可搜索海面。
- 截图固定搜索面积为 67,200 km²，已经说明分母不是整个矩形的 90,000 km²。当前标准 seed=42 的岛屿生成可能产生不同的固定面积，应读取每个 episode 的真实 mask。
- 累计覆盖 75.7% 与最近 60 分钟覆盖 11.16% 是两个指标；区域任务标记 100% 也不意味着全域完成或保持新鲜。

修复：后端帧增加 `search_domain`，由 `CoverageMetrics.fixed_mask` 发布搜索格、排除格、实际面积与尺寸。前端以灰色斜线画出排除区、勾画真实搜索域，原虚线框改称仿真网格；态势计数也采用同一搜索域。旧回放没有这个字段时明确显示缺失，不推算历史地形、不篡改已录制覆盖率。

这项修复没有擅自把真实陆地改成海洋，也没有伪造补扫。装饰背景仍不是地理配准的 GIS 地图。

## 2. 船舶交互和 AIS

已有直播场景支持从组件栏拖放 I/II 类船舶到地图，或选择类型后点击投放；支持选择并删除船舶。**不是把已存在船舶拖到另一位置的“瞬移”功能**。回放只读，截图中的按钮禁用符合这个规则。

II 类船舶可以动态开启/关闭 AIS；I 类按场景约束保持开启。AIS 开关改变发射行为，已有观测按其生命周期老化，不应瞬间抹除接触历史。没有 AIS 不等于已证实 II 类，最终分类仍依赖观测证据。

本次修复断线仍可提交、拖放与重点区域框选模式冲突、隐藏真值船舶仍能被点选、旧 episode 的异步命令结果污染新场景、连续操作使用过期 revision 等问题。命令状态应等待仿真线程的真实确认，不能将短暂排队误当成失败。

## 3. 对手建模和自主航行

对手 LLM 已接入仿真主循环，按已发现/核查/跟踪阶段为活动 II 类船舶输出航向偏置、航速、之字航向幅度、周期和相位。运动学积分、加速度、转弯、地图及航路安全仍由确定性执行器处理。LLM 不直接写每帧坐标。

已复现并修复：

1. 曾被发现的船离场后仍进入快照，与活动签名不一致，导致指挥器拒绝快照。
2. 新计划参数与旧计划相同时未重新安装，导致相位时基错误；现在新计划重新起算，缓存复用不重新起算。
3. 地图版本变化仍可能复用旧计划；现在使其失效。
4. UAV 集合为空时 `min()` 异常。
5. 闭合巡航提前跳过最后一段；调查航线误套巡航闭环规则；活动切换未使旧航行控制失效；调查速度配置没有实际执行。
6. 船舶命令的 ID、坐标类型和超大数值校验不完整。

新增 `OpponentPopulation`：默认独立 seeded RNG 每 5–15 仿真分钟尝试投放一艘，I 类概率 0.5，场内非离场船达到 12 艘时停止自动增援（人工编辑保留操作员 override）。优先边缘合法海域，避开 UAV 和已有船舶；经现有 `VesselCommandQueue` 创建和登记，排队事件与成功创建事件分开，应用时再次检查容量，避免与网页人工创建产生竞态。重置时重新初始化，不消耗导航 RNG。固定人口的历史评估场景显式关闭增援，生产默认启用。

能力边界：投放策略是随机规则，**不是 LLM 自主决定投放兵力或学会最优干扰策略**；I 类仍按正常路线航行，活动 II 类接受 LLM 逃逸参数。历史对手快照包含 UAV 运动和真实监视阶段，是集中式仿真对手信息模型，不等于完善的敌方传感器/通信/欺骗模型。没有博弈均衡、收益优化或多场景对抗优越性的证明。

## 4. 动态子区域和 UAV 指派

最新主线已经包含 pending 搜索区域复用、原子重分配、任务状态一致性、资源/航路/代际/抢占校验。程序生成合法几何，LLM 选择候选任务 ID，确定性匹配器分配 UAV；模型不能任意画矩形或绕过资源限制。分区覆盖读取实际 SAR 时间戳，转场和派任务本身不算扫描。

本次另修复两个已复现的候选窗口问题：普通搜索预留为 0 时仍多塞一个任务；小窗口按 zone ID 排序挤掉更紧急的未扫/超期区域。保留合法几何、分区配额与最终匹配的硬校验。

真实 run5 又暴露“新增配额为零便允许抢占已有搜索”的漏洞：第 32 分钟 8 架飞机被同时从搜索调去探查，第 39 分钟再抢占 1 架，SAR 始终为零。已补快照和校验器的抢占后保底约束，资源不足也不能继续削减已保留搜索力量；回归覆盖了拒绝破坏保底、拒绝恶化不足、允许真实剩余容量三种情况。修复后的真实证据以 run6 为准。

覆盖机制存在不等于全域持续覆盖已达标。需分别观察累计覆盖、30/60/120 分钟新鲜覆盖、转场时间、真正 SAR 成像、未扫格、任务释放及失效 UAV。固定速度、扫幅和飞机数量决定实际覆盖容量，不能只改调度就保证 100%。

## 5. 游戏运行入口

旧入口在模型暂停时退出 `engine.run()`、关闭帧发布器，而网页仍允许提交重试；命令可能永久排队。本次直播入口在暂停时继续由仿真线程消费运行/意图/船舶命令，重试后执行剩余步数；暂停期间不推进仿真时钟、不刷重复帧。无服务批处理仍在失败时返回。

完成步数预算后发布 `finished` 并关闭写入；`--hold-server` 保留只读查看。端口占用现在明确报错，不杀死占用端口的其他进程。

## 6. 真实模型证据

使用 `scripts/validate_live_adversarial.py`，直接创建生产 `SimulationEngine` 和真实 LongCat 网关；没有 fixture、合成 SAR、伪造目标状态或拼接帧。墙钟采用 `time.monotonic()`，每次实际推进记录帧；模型失败和未满足项原样保留。

第一轮完整证据：`outputs/validation/live-adversarial-20260922-run2/`。

- 实测 613.815 秒、35 个连续仿真分钟，末态 running，无进程异常。
- 成功模型调用：探测方 decision_maker 13、对手 red_commander 5、reviewer 2。
- 安装对手机动计划 5 次；例如 Ship-6 的航向偏置 −45°、14 节、之字幅度 20°/周期 6 分钟，随后改为 10 节。
- 随机投放 2 艘 I 类，未抽到 II 类增援，因此完整验收 `passed=false`，不是算法全部通过。
- 1 次 decision_maker 超时；多次说明文字超长导致纠错。后续提示收紧字符预算，不放宽校验。
- 转场尚未形成稳定 EO 跟踪或有效 SAR 覆盖，不能用上述调用成功证明跟踪或覆盖质量。

最终抢占修复后的 run6 连续运行 **490.745 秒**，42 个仿真分钟：红方成功 17 次、蓝方 7 次、Reviewer 2 次，7 次对手机动安装，实际释放 I 类 2 艘、II 类 1 艘。没有再抢占搜索，真实 SAR 扫描累计 6/671 栅格（0.8942%）；被动方位 3 条、联合定位 1 次。

**完整稳定性验收仍不通过**：3 次红方模型超时使 episode 无效，尚无稳定 EO 跟踪证据。脚本原 `passed=true` 只代表八项运行连通性检查，完整结论见 `run6/assessment.json` 与 [验收记录](acceptance.md)。补充固定模型运行虽完成 120 步、SAR 覆盖 31.18%，但有未定位的返航失败，也不能充当完整验收。

## 6.1 三种传感器的硬约束

| 观测 | 可发布的信息 | 信息场与覆盖 |
|---|---|---|
| 单个平台有效被动接收 | 带噪方位与接收机位置，不包含目标距离/真值位置 | 探测范围内前方走廊增加 S/A/V；不改变 SAR 时间戳 |
| 多个不同有效平台联合接收 | 同 sample/source/burst/时间、有效几何交汇后的估计位置 | 位置附近局部高斯证据增强；相应来源方位不重复计增益 |
| SAR 稳定成像 | 实际扫描足迹 | 更新信息场，并且是累计/滑窗搜索覆盖的唯一来源 |
| EO 有效目标观测 | 局部测量、取证、锁定和跟踪信息 | 刷新目标格信息；不计入区域 SAR 搜索覆盖 |

新增修复包括失效接收平台排除、异步/矛盾报告及共址/后向/退化/超范围交汇拒绝，同源独立方位不再互相覆盖，发射脉冲严格遵守开始/结束边界，方向信息核不再扩散至探测距离之外。前端方位扇形读取实际接收范围配置，定位关联半径也接入配置。

另复现 EO 刷新会增加旧累计覆盖计数的问题，已将带有 `CoverageMetrics` 的生产状态累计覆盖统一到固定域实际 SAR 时间戳。无该服务的旧版独立 StateManager 保留原兼容路径。

多平台“在范围内”仍须实际收到同一脉冲且几何可解；模型保留探测概率、测向误差与遮挡规则，不能据此声称任何两个平台都能无误差确定真值坐标。

## 7. 运行方式

在已配置真实模型凭据的环境中：

```bash
python main.py --steps 480 --step-delay 0.05 --hold-server
# 另一个终端
cd src/vis/frontend
npm run dev -- --host 127.0.0.1
```

在网页切换至直播后投放船舶，选中 II 类船舶操作 AIS。模型暂停时可重试或终止。真实墙钟验收：

```bash
python scripts/validate_live_adversarial.py --seconds 480 --seed 7 \
  --output-dir outputs/validation/<新的唯一运行目录>
```

本次不修改凭据、不清空 outputs，也不以 fixture 冒充真实 LLM。
